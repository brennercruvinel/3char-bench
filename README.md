# 3char, retrieval bench

the rig that measures how to feed [brennercruvinel/3char](https://huggingface.co/datasets/brennercruvinel/3char) to a retriever: chunk granularity, chunk form, key form and storage, on the published parquet, against a set of questions whose answers are checked against the data before anything runs.

this repo holds the experiments and their output. it does not hold the data or the models. the parquet and the two onnx embedders come from the Hugging Face Hub on first run, and every number in `rig/out/` regenerates from them with a fixed seed.

### what it found

one record per chunk, written as a sentence, embedded with multilingual e5: 92.2% recall@1 at under thirty tokens per answer. a block of records halves the recall and costs twenty times the tokens. the whole system as one chunk hits about as often as a record and costs thousands of tokens per answer, because the hit is finding the right system, not the right row.

prose beats the same fields as k=v by almost forty points of recall@1, for a third more tokens. the raw fields on their own are not enough, and dropping the noisy ones without rewriting the rest lowers recall further.

`iata:GRU` against `GRU` costs two questions on the grid. the difference appears once codes collide. across every published system, 14,911 distinct codes belong to two or more of them, `AND` to eleven. given a bare literal the retriever picks the right system a third of the time, which is the combinatorial floor. with the system name in the chunk or in the key it picks right almost every time.

there is no universal code. what joins the tables is the country, ISO 3166. for storage, JSONL plus gzip on the data and a faiss 8 bit scalar quantizer on the vectors, a quarter of the index at the same recall.

evaluating the dataset this way exposed a defect in it: `lng/ioc` shipped its aliases unlabelled, with a footnote marker where a code should be. the fix is in the pipeline, release 0.1.1.

### how it runs

```bash
bash rig/bootstrap.sh        # venv via uv, pinned deps, smoke test
.venv/bin/python rig/run.py  # six experiments, one json each in rig/out/
```

one step: `python rig/run.py grid`. one experiment on its own: `python rig/exp/collide.py`.

`CH3_HUB`, `CH3_MINILM`, `CH3_E5` and `CH3_OUT` point at local folders when the default cache is not where you want things. missing `tiktoken` gives a declared estimate, not a crash.

### layout

| path | what it is |
| --- | --- |
| `rig/lib/` | conf, catalog, qa, corpus, embed, tok, jio. the parquet reader, the answer key, the two embedders |
| `rig/exp/` | grid, decomp, collide, universal, store, hypo. one experiment per module, each writes a json |
| `rig/out/` | the json, versioned, regenerated by `run.py` |
| `rig/run.py` | runs the six in order |

the corpus is ten systems, the large ones sampled with every answer kept inside, fixed seed. the same grid over all 58 systems remains to be run.
